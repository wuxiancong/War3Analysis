# 任务：分析卡兵实测记录，找出每路卡兵成败的规律，给出数据驱动的 AI 参数

**给**：Antigravity Gemini　**布置时间**：2026-11-21　**工作目录**：`D:\Qt\workspace\War3Analysis`

## 背景

卡兵评分系统从 2026-11-21 起，每次测试都会写一个记录文件，目录是 `C:\War3Run\War3Launcher\records\block\<英雄>\`，文件名形如 `<英雄>_<路>_<时间>_<N>waves_pass<n>_avg<分>.csv`。每个文件包含：

- `#` 开头的头信息：英雄、路、模式（ai / human）、及格线、移速、射程；
- `wave` 行：`次, 波, 分, 及格线, pass/fail/skip, 用时, 到兵线用时, 详情`，详情里有漏兵数、漏兵分、拖延秒数、拖延分；
- `trace` 行：出兵后每 100ms 一行，`波, t, 英雄x, 英雄y, 兵1x, 兵1y, ...`，死兵留空。

现有 15 个文件（冰女 cm）：

| 路 | 成绩 | 说明 |
|---|---|---|
| 中路 | 23 波，平均 96 | 很好 |
| 上路 | 一次 37，修了「预判漂移」后 91 | |
| 下路 | 多次 0~47 | 大部分在光环加速期（你上一份 `dota-lane-speed-by-time.md` 已解释） |

另外还有真人录制：`artifacts/creep-block/human_block_20261118_0711.log`（中路 5 波），以及 `C:\War3Run\War3Launcher\logs\AiUnit.log` 里的「📏 真人卡兵结果」「🧭 真人坐标」。

卡兵 AI 的参数大多是一次次试出来的，散落在 `War3Launcher/hooker/war3hook_ai_tactics.inl` 的注释里，比如：

- 等兵位 = 门口 + 350 / 450；
- 前距 > 340 站住、< 300 起步；
- 横向容差 25；
- 前排宽 ≤ 110 对准中点；
- 漂移预判 0.7s，偏向漂移一侧最多 35。

现在有了逐 100ms 的轨迹，可以用数据来定这些参数。

## 要做的事

1. **按波分类**：把所有记录文件按「路 × 模式（ai / human）× 光环期（是否加速，用波次时间和兵速判断，规则见你的 `dota-lane-speed-by-time.md` §1.2）× 成绩（满分 / 漏 1 只 / 漏 2 只以上）」分组。
2. **成败对比**：对每组，用轨迹统计这些量的分布（中位数、p10、p90）：
   - 出兵时英雄领先最前兵多少、什么时候起步；
   - 前距（英雄领先最前兵）随车道距离怎么变；
   - 英雄和兵的横向差；
   - 英雄前进速度、站住时间占比；
   - 每次漏兵发生时：车道位置、横向哪一侧、漏的是近战还是远程、当时前距和英雄横移速度。
   **找出满分波和漏兵波在哪些量上差别最大。**
3. **地形 / 路段**：把漏兵位置画到车道上，对照 `dota-lane-spawn-waypoints.md`（路点）和 `war3-unit-collision-and-repath.md`（碰撞绕行），找出每一路的「难卡段」。
4. **真人 vs AI**：中路真人和 AI 在站位、起步时机、前距控制上有什么差异。中路 AI 已经 96 分，看看真人的哪些做法可以搬到边路。
5. **给出参数建议**：对上面列的每个参数，按路（中 / 边，必要时按每一路）给建议值和依据。
   - 要给出「改成这个值，预计哪几类漏兵会减少」的推断；
   - 能用轨迹离线回放验证的，写个简单模拟验证一下（比如用记录里兵的轨迹，假设英雄按新规则走，估计前距）。
6. **数据缺口**：哪些结论样本不够（比如下路非加速期、天灾三路、真人边路），要采什么数据、采多少波。
