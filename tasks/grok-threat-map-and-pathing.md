# 任务：逆向「危险地图」所需的运行时数据——实时通行、视野 / 迷雾、威胁范围（给大模型 / 本地 AI 托管走位用）

**给**：Cursor Grok　**布置时间**：2026-11-21　**工作目录**：`D:\Qt\workspace\War3Analysis`

## 背景

用户的目标是让大模型（通过 MCP Server，见 `analyses/dota-ai-llm-mcp-control.md` 和 `dota-ai-llm-mcp-verify.md`）或本地 AI 程序替玩家托管整局游戏。大模型只下「去中路对线」「回家」「去下路 gank」这样的意图，具体怎么走、走哪条路安全，要由 hook 的执行层算。现在执行层缺三样东西：

1. **实时通行**：`dota-6.83d-web-gameplay-data-reverse.md` §7 已经从 `war3map.wpm` + `war3map.doo` 得到**静态**通行图（512×512 格，每格 32）。但对局中树会被砍、被吃、重新长出来，还有其他临时阻挡，静态图不准。
2. **视野 / 迷雾**：本地玩家当前能看到哪里，敌人在迷雾里最后一次出现在哪（只能用合法的「最后可见位置」，不能读迷雾下的真实位置）。
3. **威胁范围**：塔、可见敌方英雄、兵线对一个点有多危险。这取决于射程、技能施法距离、视野范围，以及昼夜。

有了这三样，执行层才能给大模型提供一张「危险地图」：哪里安全、撤退走哪条路、哪个眼位能看到什么。

## 要回答的问题

1. **运行时通行**
   - 引擎里运行时的通行 / 寻路网格在哪：对象、偏移、格子大小、每格的位含义（可走、可建、飞行、树）。
   - 砍树 / 吃树、树重生之后，网格怎么更新，有没有可以直接读的「树是否存活」的表。可以对照已有的 `dota-6.83d-eat-and-cut-tree-reverse.md`。
   - 引擎的寻路查询函数（给定起点、终点，返回路径或可达性）。找到函数地址和调用约定，判断能否在游戏线程安全调用；结论写在文档里，不要实际调用。
2. **视野 / 迷雾**
   - 本地玩家的迷雾 / 可见性位图在哪：分辨率、位含义（从未探索、探索过、当前可见）。
   - 单位视野半径（白天 / 夜晚）的读法，以及高地视野规则（低地看不到高地）在引擎里怎么判定。
   - 怎么判断一个敌方单位「此刻可见」（`IsUnitVisible` 等的内部实现），以及怎么安全地记录「最后可见位置」。
   - **红线：只能读本地玩家合法可见的信息，文档里要明确哪些字段读了就算作弊（比如迷雾下单位的坐标）。**
3. **威胁参数**
   - 塔的射程和攻击力（Grok 的 `war3-tower-creep-aggro.md` 任务如果已经做完就引用它，没做完就只列需要的字段）。
   - 英雄技能的施法距离和作用范围：从物编批量导出，按英雄整理成表。已有 `dota-683d-ai-data-tables.md` 的话补齐缺的字段，不重复。
   - 昼夜对视野的影响。
4. **给执行层的设计**（不写代码）：危险地图怎么算、多久更新一次、多大开销，以及给 MCP 用的查询接口长什么样，比如 `is_safe(x, y)`、`safe_path(from, to)`、`last_seen(hero)`。
