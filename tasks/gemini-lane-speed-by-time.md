# 任务：六路兵线移速随时间的完整规律（实测 + 脚本 + game.dll），以及每一路该不该卡兵

**给**：Antigravity Gemini　**布置时间**：2026-11-21　**工作目录**：`D:\Qt\workspace\War3Analysis`

## 背景

你 2026-11-20 写的 `analyses/dota-lane-creep-speed-profile.md` 给出了一个关键结论：前 7 分钟，

- 优势路（近卫下、天灾上）每波刷出后 15s 内 +25%，速度 406；
- 劣势路（近卫上、天灾下）-25%，速度 244；
- 中路不变。

这个结论今天直接解释了卡兵 AI 的成绩差异：

| 路（冰女，移速 280） | 情况 | 平均分 |
|---|---|---|
| 近卫上路 | 门口起卡 | 91 |
| 近卫下路 | 门口起卡 | ~3 |
| 近卫下路 | 改到加速结束处（车道 ~6400）再卡 | 47，仍不及格 |

但那份文档里有不少「理论推导、待独立采样」的部分，**近卫上、天灾上/中/下四路没有实测**。用户还问：

> 三路兵线的移动速度是如何变化的？每一路的速度都不一样吗？难道还随时间变化？或许下路根本不需要卡兵。

所以这次要把「每一路、每个时间段、每段车道」的速度规律定死，并回答哪一路值得卡、该在哪卡。

## 要回答的问题

1. **时间维度**
   - 加速 / 减速光环（`A2V1` / `A2V0`）到底在什么条件下加：只看 `TimerGetElapsed(M) < 420`，还是还和模式（`-ap` / `-sd` / `-rd`…）、玩家人数、某一方塔是否被推有关？
   - 每波持续多久（是不是严格 15s）？到 7:00 那一刻是怎样切换的？
   - 7 分钟以后还有没有别的速度变化：兵升级（每 450s 的 `TQO`）是否带移速、超级兵 / 攻城车的移速、昼夜、夜晚视野是否影响。
2. **路的维度**：六路各自的
   - 出生朝向和转身停顿；
   - 分段速度（出兵口 → 第一个拐点 → 二塔 → 一塔 → 河道交汇）；
   - 弯道位置。
   - 已有理论值的要**实测核对**。
3. **引擎维度**
   - 光环怎么作用到移速：`A2V1` / `A2V0` 的技能类型、数据字段、buff；
   - 移速计算链（基础移速 → 加成 → `GroupSpeedMin` 等 → 32Hz 步进）。
   - **按 `.agents/rules/war3-gamedll-all-versions.md`，凡涉及 `game.dll` 必须覆盖 `War3Launcher/versions` 下全部版本，并列出各版 RVA**（不能只做 1.24.4 / 1.26 / 1.27）。
4. **实测**
   - 至少采近卫上、近卫下、近卫中各 3 波**前 7 分钟**，加 3 波 **7 分钟后**。天灾三路能采就采。
   - 采样方法：开局后用 RemoteControl `units`（`127.0.0.1:6120`，结果在 `C:\War3Run\War3Launcher\logs\AiUnit.log`）高频读兵的坐标，或只读进程内存。英雄不要挡兵（站在车道外 600 以上）。
   - 开局按 `.agents/rules/ai-autostart.md`：`Scripts\Start-AiGame.ps1 -Hero cm -MoveX <x> -MoveY <y>`。前提是 bnetd / War3Bot / Launcher 已在运行；没在运行就写清楚要谁启动，不要自己用管理员权限结束进程。
   - **不要往游戏进程写内存，不要在游戏线程以外调用 JASS 原生函数，不要往实机发卡兵指令。**
5. **对卡兵的结论**（这次最重要），每一路分「前 7 分钟 / 7 分钟后」两段给出：
   - **该不该卡**：比如优势路被加速 15s 时，英雄移速低于兵速就几乎挡不住；不卡的话兵线相遇点在哪，卡了能多拖几秒。用数据说话。
   - 如果卡，推荐起卡位置（车道距离，或世界坐标）和预期能拖多少秒。
   - 按英雄移速（≤280 / 300 / ≥310）分档的**建议及格线**。现在的及格线是：快英雄中 90 / 上 80 / 下 70，慢英雄各低 10；评分 = 漏兵分，边路再和拖延分平均。如果某一路某段时间本来就卡不住，建议「不计分」还是「降低及格线」。
