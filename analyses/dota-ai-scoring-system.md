## 一、命令

| 命令 | 作用 |
| :--- | :--- |
| `-block start [top\|mid\|bot] [ai]` | **开始连续统计这一路**（2026-11-21 改为自动判断波次）：英雄正跟着一波兵（离它 1200 内、还没到一塔）就从这一波算起，否则从下一波出兵算起；之后**每波出兵自动开始统计**，不用每波再输入。默认**真人自己卡**（AI 不动英雄，只测量打分）；带 `ai` 由 AI 每波卡。路不写 = 离英雄最近的己方那一路；换路时重新开一轮统计 |
| （自动结束） | 每一波在这些情况自动出分，计入总评：走到一塔 / 和敌方兵线接敌（满分也这样结束）；**已经不可能及格**时提前结束（边路：(当前漏兵分 + 100) / 2 < 及格线；中路：当前漏兵分 < 及格线）。统计中的这一波不会被下一波出兵覆盖 |
| （开始提示） | 出兵时不提示；英雄到了这波兵 600 内（兵营门口等兵）才提示「第 N 次测试开始（第 W 波）」 |
| （自动不计） | 本波出兵 10s 内英雄没到过这波兵 600 内（回家、打野、没去卡）→ 不提示、不计入、不记录，不拉低平均分 |
| （及格线按时段，2026-11-21） | 卡兵及格线每波按当前时段重算（屏幕提示「及格线 A → B」）：中路 快 90 / 慢 80；劣势路（近卫上 / 天灾下）减速期 85 / 75、常速期 75 / 60；优势路（近卫下 / 天灾上）常速期 65 / 50（光环期不卡不计分）。快 = 移速 ≥ 310、慢 = ≤ 280，之间线性。依据 `dota-ai-block-records-round2.md` §6.2。实测（冰女）：上路减速期 3 波 100、上路常速 8 波均 90、下路常速 8 波均 88 |
| （优势路光环期） | 近卫下路、天灾上路在地图光环期（`TimerGetElapsed(M) < 420s`，`-ap` 约游戏钟 5:15 前）兵速 406：**不卡、不计分**，屏幕提示「⏩ 光环加速期不卡、不计分」。每波刷出 2.5s 测一次领头兵速度，测到常速（300~345）即判光环期结束，下一波起从门口正常卡、计分（依据 `dota-lane-speed-by-time.md`，2026-11-21） |
| `-block wait <n>` / `-block wait auto` | 手动把近卫下路等兵位设为「二塔沿车道 + n」（正 = 往一塔方向）；`auto` 恢复自动 |
| （实测记录） | 每次 `-block start` 开一个记录文件：`hook.dll 同目录\records\block\<英雄>\<英雄>_<路>_<开始时间>_<N>waves_pass<及格次数>_avg<平均分>.csv`，每统计完一波就按最新成绩改名（崩溃也不丢）。内容：`#` 头（英雄、路、模式、及格线依据、移速 / 射程）、每波一行 `wave,次,波,分,及格线,pass/fail/skip,用时,到兵线用时,详情`，以及出兵起每 100ms 一行 `trace,波,t,英雄x,英雄y,兵1x,兵1y,...`（死兵留空），供离线学习真人站位 |
| `-block end` | 可选：停止统计并给出总评（正在走的那一波没走完，不算）。不输入也行，换项目 / 换路时会自动开新一轮 |
| `-block skip` | **这一波不算**：结束并丢掉这一波的分数 |
| `-block` | 看总评和当前状态 |
| `-block reset` | 同 `-block end`：总评并清零 |
| `-score start <block\|lasthit\|deny\|pull\|stack> [路] [ai]` | 通用开始（`lasthit` 也可写 `lh`） |
| `-score start lasthit [ai]` | 补刀计分（2026-11-21 用户要求）：不带 `ai` = 真人补、AI 不动英雄，只计分和录数据；带 `ai` = AI 模拟真人补刀。屏幕上每只兵提示 +1 / -1 和净分 |
| （玩家接管） | 带 `ai` 的测试和 `-lasthit` / `-deny` 例程：玩家一下移动 / 攻击 / 停止 / 坚守 / 巡逻指令（或右键）就立即结束，提示「[玩家接管]」，不会自己恢复。AI 补刀没有交战时原地不动，不会把英雄拉回开始测试时的位置（2026-11-21 修复，游戏内待验证） |
| （AI 补刀安全） | 不进敌方塔中心 950 内（塔射程量到碰撞边缘：700 + 144 + 32 = 876），进了先退出；英雄死亡时 AI 测试自动结束（2026-11-21 修复，游戏内待验证） |
| （补刀记录） | `records\lasthit\<英雄>\<英雄>_<路>_<时间>_lh<补到>of<机会>_dn<补到>of<机会>_pts<净分>_rate<命中率>.csv`：每只兵一行 `event`，每 100ms 一行 `trace`（英雄位置 / 血 / 伤害 / 前摇 / 冷却 / 攻击目标 + 每只兵的血和位置） |
| `-score end` / `-score` / `-score help` | 结束 / 进度 / 用法 |

**为什么不用 `-test`**：`-test` 是 DotA 6.83d 地图自己的单机测试模式命令（开启后才有 `-lvlup` / `-gold` / `-spawncreeps` 等），会冲突。地图注册的命令里没有 `-block` 和 `-score`（地图的 b 开头命令只有 `-bonus`，s 开头的 `-st` / `-stats` 不冲突）；hook 里原来也没有这两个命令。

所有结果同时：显示在游戏屏幕（自定义 UI 提示）、写 `AiUnit.log`（`🧮` 行）、追加到 `hook.dll` 同目录的 **`scores.csv`**（`time,session,row,type,hero,abbrev,lane,mode,attempt,wave,score,pass,result,detail`，row = start / attempt / summary）。

## 二、每一项怎么打分

| 项目 | 一次结果 | 分数 | 来源 |
| :--- | :--- | :--- | :--- |
| 卡兵 | 一波兵 | **漏兵分** `100 × 没漏的兵 / 本波兵数`（卡到一塔 / 兵线接敌为止）；**拖延分** `100 × min(1, 多拖的秒数 / 满分秒数)`；**边路综合 = (漏兵分 + 拖延分) / 2，中路只用漏兵分** | 现有卡兵评分器 `aiTickWaveScore`（真人 / AI 同一口径），日志 `🏁`（漏兵）+ `⏱`（拖延） |
| 补兵（含反补） | 每只死在附近的兵 | **补到 +1，没补到 -1**，净分 = 补到 - 没补到；及格看命中率 `100 × 补到 / 机会`。机会 = 英雄活着时 900 内死掉的敌方兵 + 曾低于 50% 血的己方兵；补到以 DotA 地图计数（正补 A / 反补 B）为准，兵死后 700ms 内没有计数认领 = 没补到。及格线 = 正补及格线和反补及格线（低 10）按机会数加权。`-score start deny` 只算反补 | `aiScoreLhSettle` |
| 反补 | 整个测试 | 同上，机会 = 英雄 900 内死掉的己方兵线小兵；反补数 = 地图反补计数增量 | `g_lastDeniesValue` |
| 拉野 | 一次 | 成功 100 / 失败 0（终点附近既有野怪又有本方小兵） | `aiTickLanePull`（目前只统计 AI，加 `ai`） |
| 囤野 | 一波 | 囤上 100 / 没刷新 0（xx:00 后该野点 900 内新刷野怪） | `aiTickStack`（目前只统计 AI，加 `ai`） |

**拖延分**（2026-11-20 加）：多拖的秒数 = 本波走到一塔（或接敌处）的用时 − 不卡时走到同一位置的用时。不卡用时按这一路的「自然速度」：本波兵从没进过英雄 400 内、走到一塔时记一次（平滑）；还没学到时按 340/s（近卫下路 8722 / 340 = 25.6s，与真人录制里不卡的波 25.5s 一致）。满分 = 比不卡多走 50% 的时间（近卫下路约 13s）。
为什么加：真人近卫下路录制（22:58~23:25）里，真人卡的波用时 30~48s（不卡 25.5s），第 9 波多拖 17s，但最后 4 只都溜过去（漏兵分 0），只看漏兵就和完全没卡一样。真人漏兵的位置也集中在车道 3300~6000 外侧（横向 −170~−200），说明下路这个弯道对真人也难，下路及格线定低是合理的。

总评：卡兵 / 拉野 / 囤野 = 各次平均分 ≥ 及格线（卡兵边路用综合分）；补兵 / 反补 = 总比例 ≥ 及格线，且机会 ≥ 5 才判定。

## 4.5 2026-11-21 修正：为什么总评总是「0 次」

- 现象：5 次 `-block start` / `-block end` 总评都是「0 次，平均 0 分」。
- 原因：一波兵的分数要等兵走到一塔才出（出兵后 25~40s），用户每次都在本波刚开始几秒就 `-block end`，会话已经关了，这一波的分数被丢掉。分数本身是对的：被丢掉的 3 波综合 22 / 41 / 36（漏兵 0 / 50 / 50，多拖 5.6 / 4.0 / 2.9s）。
- 修正：
  - 本波开始测量时屏幕提示「第 N 波开始测量 … 兵走到一塔（约 25~40s）出分」；
  - `-block end` 时本波还在测 → 提示并等本波出分（最多 60s）后自动结束；再输入一次 `-block end` 立即结束（这一波不算）；
  - 中文路名：war3 聊天文本是 GBK（「下」在日志里是 `ÏÂ` = `CF C2`），原来只认 UTF-8。用户要求**取消中文，只用英文**：路名只认 `top` / `mid` / `bot`（`bottom`），如 `-block start top`。
