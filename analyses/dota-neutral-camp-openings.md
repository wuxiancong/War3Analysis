## 一、结论

| 问题 | 结论 |
| :--- | :--- |
| 旧文档「建议拉出方向」（最近的封野盒边）能用吗？ | **不能。** 12 个野点里该方向全部被树或悬崖挡住（直线可走只有 96～384 码），这就是 AI 走不到等待位、野怪 3/3 看不见、15 次出手 0 次打中的原因。 |
| 开口怎么定义？ | 从出生点出发、在通行网格（wpm NoWalk + 树木 2×2 格，且上下左右邻格可走）上寻路，能走到**封野盒外 ≥ 200 码**、路程 ≤ 1500 的出口；按方位角分 15° 扇区，相邻扇区合并成开口。 |
| 拉野路线 | 每个开口的每个扇区取最短路：**A** = 路上离出生点约 520、视线不穿树、悬崖层不低于出生点的站位；**B** = 出口点（已出封野盒）。 |
| AI 怎么用 | 每波在该野点的路线里**随机挑一条**（尽量和上一波不同）：站 A，:50～:53 打一下最近的看得见的野怪，走到 B 再顺 A→B 方向多走 300。 |

## 四、方法细节与局限

| 项 | 取值 / 说明 |
| :--- | :--- |
| 通行 | wpm `0x02` NoWalk 为不可走；树木按 2×2 格（64×64）叠加；格子本身和上下左右邻格都可走才算能过（≈ 单位碰撞宽度） |
| 寻路 | 8 邻接 Dijkstra，斜走不切角；路程上限 1500 |
| 出口 | 离封野盒（r1 rect）≥ 200 码的可达格 |
| A 视线 | A→出生点连线不穿树 / YTlb，A 的悬崖层 ≥ 出生点 |
| 每野点路线 | 每 15° 扇区一条，A 相距 < 150 去重；只保留看得见出生点的；最多 6 条（按方位均匀抽） |
| 站位约束（第二轮） | A 离自己出生点 480～640；A、B 离**其他野点**封野盒 ≥ 300（第一轮 F5 的 A 贴着 W5 盒边，影魔被打死；W5 一条 B 离 F5 盒只有 16） |
| 未建模 | 地图运行中被砍掉的树（开口会变大，不会变小）；野怪实际站位偏离出生点；守卫距离 600 的追击 / 回巢时间 |
