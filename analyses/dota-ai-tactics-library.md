## 一、结论

| 问题 | 结论 |
| :--- | :--- |
| 怎么组织？ | **技巧 = 触发条件 + 带真人延迟的动作序列**。两级作用域：**通用**（所有英雄）/ **英雄专属**（表内英雄）；11 个分类：打野、击杀、逃命、补刀、插眼、推线、团战、加点、肉山、防御、欺骗。 |
| AI 怎么用？ | 每个技巧可 `tactic on/off` 自动触发，也可 `tactic run` 手动执行一次；调度按优先级 **逃命 > 救队友 > 切鬼手 > 击杀 > 团战 > 推线 > 打野/加点**，同一时刻只执行一个动作序列；执行期间补刀例程让出控制权。 |
| 需要新逆向吗？ | **不需要新 game.dll RVA。** 新增的都是按名缓存的只读 JASS 原生（物品栏、三维、蓝量）+ 已有 Enqueue 动作包（`useslot1..6 = 0xD0028..0xD002D` 用物品）。 |
| 全都能做吗？ | 不能。**26 项里 18 项已可执行（READY）**，8 项缺底层能力（树木目标、弹道识别、眼位/地形坐标库、Shift 队列标志位、卡尔切球状态、骨法守卫类型、肉山流程）只入目录，`tactic run` 会说明原因。 |

## 四、架构

```text
RemoteControl / 游戏内  tactic list|status|stop|on|off|run
        │  (AI_UNIT_CMD_TACTIC，aux = 技巧 ID / 0x8000|分类 / 0xFFFF 全部)
        ▼
 war3hook_ai.cpp  aiTick (10ms, 游戏主线程)
        │
        ├─ aiTickTactics
        │     ├─ aiScanCamps            每 1s：Player(12) 中立单位首现位置聚类 → 野点表
        │     ├─ aiTickTacticRun        执行当前动作序列（MOVE/ATTACK/STOP/CAST/ITEM，步间真人延迟）
        │     ├─ aiTickCreepBlock       状态机：新一波 → 领头兵前方 Z 字走位
        │     ├─ aiTickStack            状态机：:45 就位 → :53 出手 → 带走 → :00 计数
        │     ├─ aiTickFarmStacked      清野（含英雄清野技能）
        │     └─ 每 200ms 按优先级评估已开启的技巧 → 触发 aiStartTacticRun
        │
        ├─ aiTickRoutine（补刀）     g_aiTacticBusyUntil 期间让出；成功补刀回调 aiTacticOnLastHit
        └─ 施法保护 g_aiCastGuardUntil  技巧施法也会设置（持续施法不被打断）
```

### 新增底层能力

| 能力 | 实现 | 说明 |
| :--- | :--- | :--- |
| 蓝量 / 最大血量 | `GetUnitState(u, 2)` / `(u, 1)` | 连招判断「蓝够全套」 |
| 物品栏 | `UnitItemInSlot(u, 0..5)` + `GetItemTypeId` | 地图调用 207 / 160 处，按名缓存；物品类型码 → 标签表 `kAiItemCodes`（来自 `dota_data.json` realCode 组，含充能 / 等级变体） |
| 用物品 | `useslot1..6 = 0xD0028..0xD002D`，0x10 / 0x11 / 0x12 | 冷却按物品类型自行计时 |
| 技能耗蓝 / 冷却 | 技能表新增 `manaCost` / `coolDs`（地图 SLK `Cost1` / `Cool1`） | 施放后自行计时（1 级冷却，偏保守） |
| 主属性 | `GetHeroStr/Agi/Int(u, true)` 取最大 | 阵容加点 |
| 游戏钟 | 兵线 0:00 起每 30s 一波；`aiOnUnitCreated` 见到兵线单位创建即校准，偏差 >2s 按 30s 整倍数重对齐 | 拉野时机 xx:53 |
| 野点 | Player(12) 中立单位首次出现位置，450 内归同一野点 | **不写死坐标**，任何地图版本可用 |

## 五点五、卡兵成功的判定与成功率

### 怎么验证卡兵成功

卡兵的目的不是「把兵挡住不动」，而是**让己方兵线晚到河道**，两边兵在更靠己方塔的位置相遇（中路对线更安全，敌方要多走路才能补刀 / 压线）。所以用**结果**判定，不用「走了多少步」：

```text
起点   = 刷兵 1s 后领头兵位置（兵营门口）
终点   = 领头兵走到河道（中路距地图中心 ≤ 1300）
实际用时 = 终点时刻 - 起点时刻
理论用时 = 起点到终点的直线距离 / 兵速 325
延迟   = 实际用时 - 理论用时
延迟 ≥ 2.0s → ✅ 卡兵成功（相遇点约往己方移 325 以上）
```

- **基线**：`tactic run block 1` 只测量不卡。兵互相挤、绕路本身也会有一点「自然延迟」，卡兵延迟要明显高于基线才算有效。
- 每波日志：`📏 卡兵结果 第 N 波：到河道 x.xs，直线 d，理论 y.ys，延迟 z.zs ✅/❌ | 成功 s/w（%）平均延迟`；`tactic status` 汇总成功率 / 平均延迟 / 基线 / 无效波数。
- 领头兵途中死亡（被敌方英雄打死等）的波记为**无效**，不计入成功率。
- 只统计**中路**（领头兵在地图对角线附近）。

### 能不能保证 100% 成功

**不能保证 100%**，只能把成功率尽量做高并用数据证明。原因：

| 因素 | 说明 |
| :--- | :--- |
| 刷兵时英雄不在门口 | 回城、被追、在打野、补给时错过本波（连续模式会提前 12s 回门口，但英雄死亡 / 被拖住时赶不上） |
| 兵的寻路是引擎决定的 | 兵发现前方被挡会绕行，绕行方向与碰撞体积、地形（中路坡道、树、塔）相关，每波略有不同 |
| 真人化抖动 | 走位间隔 150~520ms、左右摆动是刻意加的随机，偶尔会让兵从侧面绕过去 |
| 英雄体型与移速 | 碰撞体积小 / 移速低的英雄卡兵效果本身更差（这是游戏机制） |
| 远程兵 / 攻城车 | 只卡领头近战兵；后面的兵不受影响 |
| 对手干扰 | 敌方英雄压过来、打断走位时只能放弃 |

能提高成功率的方向（按需再做）：根据兵的实际运动方向调整挡位侧（兵往左绕就往左挡）；每波前精确站到兵营门口正前方；碰撞小的英雄降低期望。**验收标准建议用「成功率 + 平均延迟高于基线」而不是 100%。**

### 为什么「始终卡住最前面的兵」这么难（2026-11-18，按第六轮 376 个轨迹采样分析）

> 问：每个兵的位置都能算出来，始终卡住最前面的兵不就行了？后面的兵冲到前面时就换着卡。

现在的代码**已经是这么做的**：每 ~170ms 重新读本波所有己方兵的位置，取沿车道最靠前的那只当目标；后面的兵超上来，目标就切换。难点不在「知道兵在哪」，而在「英雄的身体能不能一直挡在它前面」。轨迹（英雄相对最前兵，正 = 在前）：

| 出兵后 | 平均前距 | 在兵前占比 | 平均横向偏差 |
| :--- | ---: | ---: | ---: |
| 0s | +191 | 96% | 70 |
| 1s | +30 | 72% | 75 |
| 2s | −75 | 40% | 126 |
| 3s | −175 | 32% | 145 |
| 4s | −287 | 15% | 106 |
| 5s | −324 | 9% | 81 |
| 8s | −510 | 0% | 42 |

1. **英雄比兵慢，一旦被超就永远追不回来**：冰女 280，兵 325。开局领先 ~190，只够「贴身」1~2 秒。之后被任何一只兵平齐，英雄就只能在后面追；「换着卡最前面的兵」在物理上做不到——新的最前兵已经在英雄前面了。
2. **英雄没对准兵的路线**：横向偏差 70~145，而英雄碰撞半径只有约 30。兵不是「撞上英雄被挡住」，而是从旁边直接走过去了。每次横移去补位都会损失前进速度（实测前距每秒掉 ~100，比 325−280=45 的速度差大一倍多），越补越落后。
3. **反应慢半拍**：采样 ~100ms + 下令 + 游戏执行，兵在这段时间走 50~100，比英雄身体还宽。只看「兵现在在哪」去追，永远晚一步，必须预测。
4. **兵会主动绕**：War3 寻路发现前面被挡就立刻换路线；挡住它靠的是让它反复重寻路，需要英雄正对兵的行进方向，偏一点兵就从侧面过去了。
5. **测量也有干扰**：第 13 波以后两边兵在测量点前交战，被拖慢的延迟会被误算成卡兵效果（见上）。

**真人是怎么做到的**：真人不是「看到兵再去挡」，而是**提前知道兵要走的路线**（每波兵走的线基本一样），从出兵起就站在这条线上、在兵前一点点，只做很小的左右修正和停顿。领先距离是一点点「花掉」的，不会去横向追兵。

**改进方向（未实现）**：

1. **学兵线路径**：基线波（不卡）记录最前兵每 100ms 的位置，拟合出这条中路的「兵走的线」（折线）。卡兵时英雄始终站在这条线上、最前兵前方 30~60 处，横向只做 ±20 的修正，不再追侧面的兵。
2. **出兵前就位**：出兵前站到路线起点（兵营门口沿路线前方 ~100），让兵一出门就在英雄正后方。
3. **按预测下令**：用兵的速度 ×（采样 + 执行延迟 ~0.25s）预测兵的位置，而不是用当前位置。
4. **放弃判断**：一旦最前兵领先英雄（前距 < −30），本波直接停止卡兵（追不回来，继续只会浪费走位），记为失败。
5. 测试改为基线 / 卡兵交替（见下一步 1）。

下一步：

1. **基线和卡兵交替测**（奇数波基线、偶数波卡兵），或基线也测到第 20 波以后，让两者处在同样的兵线阶段；否则后期交战会被算成卡兵效果。
2. 测量只取开局前几波（如第 1~8 波各自重开一局），或测量终点改得更近（如 1000），避开交战。
3. 保留「在兵前占比」作为必要条件。
