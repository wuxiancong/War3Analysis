## 结果

**真人 2 : AI 0**，AI 负（09:07:05 一血，09:09:02 第二杀，约 8 分钟）。AI 补刀 3/8，反补 2/11。

## AI 阵亡原因

| 次 | 过程 | 根因 |
| :--- | :--- | :--- |
| 1（09:07:05） | 对线中反复「在挨打 → 退一步 → A 己方兵甩仇恨 → 回去补刀」，血 374 → 296 → 172 → 123/530 才「血太少：退到塔后」，来不及 | ① 全程**没有任何敌方英雄相关日志**（安全距离 / 压制 / 拉兵线 / 击杀都没触发）→ 很可能没识别出敌方英雄（`aiBuildCtx` 的 `enemyHeroes` 或 `g_aiDynamicEnemies` 为空）；② 回塔阈值太低（~23%），被兵 + 英雄同时消耗时来不及 |
| 2（09:09:02） | 复活后 `-score start laning` 从头开始：又买一遍出门装（第二只小鸡，剩 314 金）→ 去插「中路随机高坡线眼」(-109,-573)（天灾中路高坡，对手一侧）→ 插完 1.6s 后阵亡 | ③ 对线流程只按「开局从基地出发」设计，中途复活重启会重复买出门装、去危险位置插眼；④ 同 ①，对手就在旁边完全不防 |

## 下一轮修复清单（按优先级）

1. 敌方英雄识别：查清 solo 中为什么对线博弈逻辑一次都没触发（对手在天灾槽位、房间里有 8 个电脑玩家）。
2. 控血线：被小兵连续打 / 血量 < ~50% 且对手英雄在附近时退出兵堆；回塔阈值上调。
3. 复活后重启对线：跳过出门装和插眼，直接上线；不去对手一侧高坡插眼（solo 只插己方一侧）。
4. SOLO 模式命令：查真实聊天发送后地图不认的原因（发送时机？聊天范围？是否必须是第一个玩家的「本地输入」）。
5. Launcher IPC 缓冲区：hook 不在线时不写或丢弃旧消息；进房通知失败不应解散房间。
6. **真人控制时不能有任何 AI 参与**（用户反馈本局操作卡顿、「像 AI 也在一起控制」）：
   - 本局真人是直连魔兽（宿主机没有 hook），AI 代码不可能给真人英雄下指令。卡顿来自**锁步同步**：VM 里 AI 那台客户端只有 ~12 FPS（`[AiTick]` 平均 78~91ms，单次最长 438ms / 563ms），所有客户端都要等它，真人的指令被拖慢。AI 的防自动平 A 护盾每 5s 还会按二三十次 S，也占同一个同步通道。
   - 对策：AI 客户端所在机器要有余量（Launcher 本身常年吃 44%+ CPU，见 sf 补刀文档「环境的坑」）；护盾按 S 只在补刀例程运行时进行（已如此），可再降频。
   - **已改（编译通过，未部署 / 未实机验证）**：`war3hook_ai.cpp` 玩家接管时停掉**所有**会下指令的 AI 功能——原来只停补刀 / 对线 / 待加点 / 计分，自动加点、自动避险、已开启的技巧（卡兵 / 囤野 / 拉野 / 补刀走位 / 阵容加点）和待放技能都还会继续动玩家英雄。
