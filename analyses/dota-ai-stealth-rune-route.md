## 一、地图数据模型与视野规则依据

从 DotA 6.83d 地图解包（`artifacts/ward-deward/map/`）读取原始二进制与 SLK 数据：

1. **通行与地形（`war3map.wpm` + `war3map.w3e` + `war3map.doo`）**：
   - `war3map.wpm`：`512×512` 格（每格 `32×32` 世界单位），原点 `(-8192, -8192)`，`bit 0x02` 为不可步行。
   - `war3map.w3e`：`129×129` 格点（每格 `128×128`），记录悬崖层 `layer_height`（近卫/天灾中路一塔均为 **cliff 9**，中路河道与上下符点均为 **cliff 8**）。
   - `war3map.doo`：共 `5,198` 个装饰物/可破坏物，其中活树 **`3,675` 棵**（`ATtr` 2,061 棵、`NTtw` 1,551 棵、`NTtc` 63 棵），视线阻挡物 `YTlb` 等 **`195` 处**。
   - **重要校验**：`war3map.wpm` 原生仅将 **`20.9%`** 的树木中心标为不可走，其余 79.1% 的树木通行阻挡由引擎加载 `war3map.doo` 动态写入（每棵树占 `2×2` = `64×64` 格）。本分析已将全部 3,675 棵树叠加到通行网格，并在 8 邻域 A* 中禁止斜向穿墙角，以准确还原 War3 寻路。
2. **敌方视野源与遮挡规则**：
   - **中路一塔**：天灾 `u00M` `(1056, -96)`、近卫 `e00R` `(-1504, -1824)`，白天 **`1900`** / 夜晚 **`800`**（见 [`war3-tower-creep-aggro.md`](./war3-tower-creep-aggro.md) 与 `Units_UnitBalance.slk`）。同时额外核查了双方中二塔、上/下路一塔（1900），全部 4 条路线均在其范围外（`0` 暴露）。
   - **中路敌方小兵**：6.83d `Units_UnitBalance.slk` 实值——`edry`（近卫远程兵）`Y=86` **`sight=850 / nsight=800`**，`ugho`（天灾近战兵）`Y=112` **`sight=850 / nsight=800`**，`umtw`（攻城车）`Y=114` `sight=850 / nsight=850`。交战点按中路河道中心 `(-450, -450)` + 敌侧前排兵偏移 180 码建模。
   - **视线遮挡（参考 `dota-683d-vision-and-fog-juke.md` 与 `warcraft-iii-fog-of-war-implementation.md`）**：
     - **高地挡低地**：`cliff(目标) > cliff(观察者)` 不可见；射线中途经过 `cliff > max(观察者, 目标)` 不可见。（斜坡 `ramp` 边缘连续高度过渡处可能存在半格误差，标 `❓`。）
     - **树木与 `YTlb` 挡视线**：`ATtr/NTtw/NTtc` 遮挡高度 `occH = 230`（高于 1 层悬崖 128），射线高度低于 `tree_cliff * 128 + 230` 时阻挡；`YTlb`（`occH = 1000`）始终阻挡。

## 二、Claude 现有四条路线逐项核验（可走性 + 寻路绕行 + 视野）

来源：[`stealth_routes_report.txt`](../artifacts/stealth-rune-route/stealth_routes_report.txt) 与 [`refined_routes_report.txt`](../artifacts/stealth-rune-route/refined_routes_report.txt)。

### 2.1 近卫 → 下路符 `(-412,-1482) → (1468,-3060)`
- **路点本身**：两点均 `walkable=True`（均为 `cliff=9`，距天灾一塔 `2019` / `2992` > 1900，塔看不到）。
- **段间直通与绕行**：
  - 段 1 `(-800,-950)→(-412,-1482)`：直通 `False`，A* `816` vs 直线 `658`（`1.24x`），因树木绕行至 `(-784,-1296)`（最大偏离 `191` 码）。
  - 段 2 `(-412,-1482)→(1468,-3060)`：直通 `False`，A* `2562` vs 直线 `2454`（`1.04x`），绕行较轻微（最大偏离 `150` 码 @ `(400,-1968)`）。
  - 段 3 `(1468,-3060)→(3008,-2832)`：直通 `False`，A* `1793` vs 直线 `1557`（`1.15x`），因近卫野区南侧悬崖与树林向北绕至 `(2288,-2672)`（偏离 `264` 码）。
- **视野评估**：**这条是 Claude 现有 4 条里视野最好的一条**。高坡起点白天塔暴露 `0` 码（直线会暴露 `2400` 码！），兵线暴露仅起点 `100` 码；总路程 `5171` 码（比直线多 `+1.90s`）。优化空间在于微调路点省去段 1/段 3 的小折返，可提速 `0.44s`。

### 2.2 近卫 → 上路符 `(-1596,-330) → (-2232,80)`
- **路点本身**：两点均 `walkable=True`（均为 `cliff=9`，距天灾一塔 `2662` / `3293`）。
- **段间直通与绕行（❌ 严重撞墙绕大圈）**：
  - 段 1 `(-800,-950)→(-1596,-330)`：直通 `False`，直线仅 `1009`，**实际 A* 绕出 `1488`（`1.47x`）**，被近卫中路西北悬崖与树墙彻底堵死，War3 寻路被迫先向西绕到 `(-1680,-784)`（最大偏离 **`410` 码**）再折返往北！
  - 段 2 `(-1596,-330)→(-2232,80)`：直通 `False`，直线仅 `757`，**实际 A* 绕出 `1159`（`1.53x`）**，被迫往西北绕到 `(-2032,272)`（最大偏离 **`270` 码**）！
  - 段 3 `(-2232,80)→(-2352,1648)`：直通 `False`，A* `1674` vs 直线 `1573`（`1.06x`）。
- **视野与耗时评估**：虽白天塔暴露 `0` 码，但总路程高达 **`4320` 码（`14.17s`，比直线白白多跑 `+3.54s`！）**，且高坡起点还因 `aiStealthNext` L415 阈值 `1950` 不会触发。

### 2.3 天灾 → 上路符 `(-520,-76) → (-1224,704)`
- **路点本身**：两点均 `walkable=True`（均为 **`cliff=8` 河道层**，距近卫一塔 `2006` / `2543`）。
- **段间直通与绕行**：段 1 直通 `True`（`1.02x`），段 2/段 3 轻微绕树（`1.07x` / `1.02x`），总路程 `3063` 码（仅多 `+0.31s`）。
- **视野评估（❌ 贴河暴露给中路兵线）**：WP1 `(-520,-76)` 距中路河道交战点 `(-450,-450)` 仅 `380` 码且同在 `cliff=8` 河道！导致英雄在 **`(-462,-112) → (-915,243)` 整整 `650` 码**内全程暴露在近卫中路小兵视野下（河道起点更是 `950` 码），**比直接右键走直线（`600` / `850` 码）暴露得还多**。

### 2.4 天灾 → 下路符 `(3160,-2232)`
- **路点本身**：`walkable=True`（`cliff=8`，肉山外侧东岸，距近卫一塔 `4682`）。
- **段间直通与绕行**：段 1 `(-100,-100)→(3160,-2232)` 直通 `False`，A* `4176` vs 直线 `3895`（`1.07x`，最大偏离 `304` 码 @ `(2544,-2192)`）；段 2 直通 `True`。
- **视野与耗时评估**：
  - 高坡起点：0 暴露，但绕到肉山外侧多跑 **`+1.45s`**（`4837` vs 直线 `4394`）。
  - **河道起点隐患**：若英雄从中路河道 `(-450,-450)` 直接往 `(3160,-2232)` 走，A* 前半段会顺河道往东南走，导致**白天塔暴露 `750` 码、兵线暴露 `950` 码**（而先爬天灾高坡 `(1100,-600)` 可压到仅 `300` 码且更快 `1.15s`）。

## 三、推荐更优隐蔽路线详述与叠图

> 矢量叠图见 [`artifacts/stealth-rune-route/stealth_routes_overlay.svg`](../artifacts/stealth-rune-route/stealth_routes_overlay.svg)（红虚线 = Claude 现有 A* 轨迹，绿/青/紫/橙实线 = 推荐隐蔽路线，蓝/红虚圆 = 双方中一塔白天 1900 / 夜晚 800 视野，黄虚圆 = 中路河道兵线 850 视野，深绿圆点 = 3,675 棵树）。

1. **近卫 → 下路符**：`(-464, -1584)` → `(1468, -2960)` → `(2320, -2672)`
   - 走法：从近卫中路高坡贴南翼树林进己方野区（`cliff=9`），经 `(1468,-2960)` 贴树向东，从 `(2320,-2672)` 下河道拾取下符。
   - 性能：高坡起点 `5035` 码（`16.51s`，比直线 `+1.46s`），**塔白 0 暴露**、兵白仅起点 100 码；各段绕行比 `1.05x~1.10x`。
   - 最短不可避免暴露：若在中路河道 `(-450,-450)` 起步，退回近卫高坡前必经 `450` 码塔白暴露（`(-464,-464)→(-679,-775)`，约 `1.48s`）及 `750` 码兵线暴露。
2. **近卫 → 上路符**：`(-1648, -784)` → `(-1840, 200)`
   - 走法：从近卫高坡直线直通 `(-1648,-784)`（绕开中路西北树墙），再贴近卫西侧高坡树林向北经 `(-1840,200)` 下上河道。
   - 性能：高坡起点 `3673` 码（`12.04s`，比直线 `+1.41s`，**比 Claude 快 `2.13s`**），**塔白 0 暴露**、兵白仅起点 200 码；各段绕行比 `1.08x~1.09x`。
   - 最短不可避免暴露：河道起步时，退上近卫高坡必经 `400` 码塔白暴露（`(-464,-464)→(-740,-644)`，约 `1.31s`）。
3. **天灾 → 上路符**：`(-400, 560)` → `(-1360, 1136)`
   - 走法：从天灾高坡直接向北切入天灾野区 `(-400,560)`（`cliff=9`，高地+树林双重遮挡中路兵线），再经 `(-1360,1136)` 贴北岸树林切入上符。
   - 性能：高坡起点 `3194` 码（`10.47s`，比直线仅 **`+0.74s`**），**塔白 0 暴露 + 兵白 0 暴露（全程隐身）**；各段绕行比 `1.07x~1.09x`。
   - 最短不可避免暴露：河道起步时，向北爬上天灾坡必经 `250` 码塔白暴露（`(-464,-464)→(-464,-264)`，约 `0.82s`）及 `400` 码兵线暴露。
4. **天灾 → 下路符**：`(1100, -600)` → `(1712, -1296)`
   - 走法：沿天灾高坡南侧（`cliff=9`）经 `(1100,-600)` → `(1712,-1296)` 直下下符，**三段全部 100% 直线直通（`True / True / True`）**。
   - 性能：高坡起点 `4450` 码（`14.59s`，比直线仅 **`+0.18s`**，比 Claude 快 `1.27s`），**全程 0 暴露**；河道起步时立刻向东爬坡脱雾，塔/兵暴露均仅 **`300` 码**（`(-464,-464)→(-214,-464)`，约 `0.98s`）。

## 四、说明与未验证边界（`❓`）

- **全版本 `game.dll` 说明**：本任务仅使用 DotA 6.83d 地图静态数据（`wpm` / `w3e` / `doo` / `UnitBalance.slk`），未新增 `game.dll` 逆向函数；若需运行时查询 `IsUnitVisible` 全 11 版本 RVA，见前序 [`dota-683d-vision-and-fog-juke.md`](./dota-683d-vision-and-fog-juke.md) 与 `artifacts/ward-deward/visibility_natives.md`。
- **`❓` 边界项**：
  1. 本模型未计入敌方中单英雄主动前压/游走视野及敌方河道假眼（此类动态视野需在运行时结合 `IsUnitVisible(myHero, enemyPlayer)` 反应）。
  2. `war3map.w3e` 斜坡（`ramp`）半格过渡带的连续高度视线判定在引擎底层可能有 ±64 码误差，本文对高坡退雾点已留出 100~200 码以上安全余量。
  3. 实际 War3 寻路使用导航网格平滑 + 单位动态避障（若路上有己方/野怪单位阻挡可能产生小幅临时偏移），尚未开游戏实机跑图复核。
