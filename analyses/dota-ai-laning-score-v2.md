# 对线计分 v2：补刀 + 受伤扣分 + 对英雄伤害加分（设计稿）

| 字段 | 内容 |
| :--- | :--- |
| **分析模型** | Claude Opus 5.5 |
| **分析目的** | 用户要求对线计分不只看正补 / 反补，还要算「受到伤害扣分（英雄、小兵、塔都算）」和「对敌方英雄造成伤害加分」。评估现有计分系统的缺口，给出 v2 设计 |
| **命名方式** | `dota-ai-laning-score-v2`（替代 `dota-ai-scoring-system.md` 里「补兵」一项的口径；卡兵 / 拉野 / 囤野不变） |
| **分析时间** | 2026-11-24 |
| **验证状态** | **设计稿，未编码**。权重待用户确认；伤害来源归属依赖 Gemini 任务 `tasks/gemini-damage-event-attribution.md` |

## 一、现有计分的缺口

现行口径（2026-11-24 起）：`得分 = 正补命中率 + 反补命中率 × 0.1`，及格线 = 英雄的正补及格线（影魔 88）。

| 缺口 | 后果 |
| :--- | :--- |
| 不计受到的伤害 | 站在塔下挨打、被小兵追着打，只要刀补到了照样满分；实测 AI 多次「在挨打：往后退一步」「A 己方兵甩仇恨」，完全不影响分数 |
| 不计对敌方英雄的伤害 | solo 时换血 / 消耗（对线的另一半）完全不体现 |
| 死亡只结束测试 | 死一次和不死、补到同样多的刀，分数一样 |
| 机会数 < 5 就不判定，长短局不可比 | 伤害类指标一定要按时间归一，否则测得越久扣得越多 |
| 没有来源拆分 | 不知道伤害是吃了塔、小兵还是英雄，没法针对性改 AI |

## 二、v2 设计

**总分 = 补刀主分 + 交换分 − 受伤扣分 − 死亡扣分**，上限 100，下限 0。所有伤害类指标按「每分钟、占最大血量的百分比」归一，与测试时长和英雄等级无关。

| 项 | 公式 | 默认权重（待确认） | 例子 |
| :--- | :--- | :--- | :--- |
| 补刀主分 | 正补命中率 + 反补命中率 × 0.1 | 现行不变 | 正补 84%、反补 25% → 86.5 |
| 受伤扣分 | Σ 来源（受到的伤害 ÷ 自己最大血量 ÷ 分钟 × 100）× 系数 × **0.5** | 系数：塔 1.5、小兵 1.0、英雄 1.0 | 每分钟掉 20% 血（全是小兵）→ −10；同样的量是吃塔 → −15 |
| 对英雄伤害加分 | （对敌方英雄造成的伤害 ÷ 敌方最大血量 ÷ 分钟 × 100）× **0.5**，封顶 +15 | 普攻、技能都算；只算英雄本体（不算幻象 / 召唤物） | 每分钟打掉对面 20% 血 → +10 |
| 击杀 / 死亡 | 击杀 +10；死亡 −20（死亡后测试照常结束） | | |
| 回血 | 不抵扣受伤（喝瓶、吃药是消耗，不是表现） | | |

- 及格线：仍按英雄（影魔 88）。单人无敌方英雄的测试里，交换分恒为 0，只有扣分项，相当于「补刀 + 少挨打」。
- 屏幕和日志分项显示：`正补 x/y（%）反补 x/y（%）| 受伤 −a（塔 −b 兵 −c 英雄 −d）| 对英雄 +e | 死亡 −f | 得分 S`。
- `records\lasthit\` 的 CSV 增加 `dmg,<t>,<来源类型 tower|creep|hero|other>,<来源句柄>,<目标 self|enemyhero>,<伤害>` 行，供离线复盘。
- `scores.csv` 的 summary 行增加 `taken_tower,taken_creep,taken_hero,dealt_hero,kills,deaths`。

## 二点五、更多对线指标（2026-11-24 用户追加）

| 项 | 怎么算 | 默认权重（待确认） | 数据来源 |
| :--- | :--- | :--- | :--- |
| **待在经验范围** | 敌方兵线小兵死亡时，自己活着且在经验范围内的比例（范围待 Gemini 核：引擎默认 1200，地图可能改） | 比例 × 0.1（最多 +10；低于 70% 时按差额扣，最多 −10） | 小兵死亡已有记录（补刀机会统计），只多算一个距离 |
| **等级 / 经验压制** | 自己经验 − 对方经验，换算成「领先几级」（按 DotA 升级经验表折算小数级）。每领先 0.1 级 +1，落后同样扣，±15 封顶。测试结束时取值，过程中每 30s 记一次曲线 | ±15 | `GetHeroXP` / `GetHeroLevel` 原生（已有调用方式）。**敌方只在可见时采样**，不可见沿用最后一次读数 |
| **控符** | 每次刷符（偶数分钟，一强化一金币）：自己吃到 / 装瓶 +，被对面拿走 −，都没人拿不计 | 每个 +3 / −3，±12 封顶 | 已有「神符已装瓶 / 已吃掉」判定；「被对面拿走」= 符消失时对面英雄离符点 < 200 且可见（否则记「不明」，不扣） |
| **插眼** | 河道眼在场时间占测试时长的比例；插眼失败（充能没减）扣 | 比例 × 5；每次失败 −1 | 已有「只认充能减少」判定 |
| **排眼** | 看见（显形）的敌方眼被自己排掉 / 看见的敌方眼总数 | 每排一个 +3 | 需要识别敌方眼单位（`o004` 假眼 / `oeye` 真眼）和真视来源；单人测试不出现 |

单人无敌方英雄的测试里，压制、控符被抢、排眼都恒为 0，不影响及格判定。

**分项公示**：屏幕和日志按「补刀 / 经验范围 / 压制 / 受伤 / 对英雄伤害 / 控符 / 眼 / 击杀死亡」逐项显示加减分，总分仍封顶 100。

## 三、怎么量伤害（实现方案）

| 方案 | 做法 | 精度 | 风险 |
| :--- | :--- | :--- | :--- |
| A. 血量差分 | 每帧读自己 / 敌方英雄血量，下降量计为伤害；来源按「当帧打到我的在途弹道 + 前摇刚结束、目标是我的攻击者」归属 | 中：回血 / 回蓝符、同帧多来源会混；归属靠猜 | 不需要新的 game.dll 地址，可以马上做 |
| B. 引擎伤害事件 | 在 `game.dll` 结算伤害的函数（触发 `EVENT_UNIT_DAMAGED`、给 `GetEventDamage` / `GetEventDamageSource` 准备数据的地方）挂钩，直接拿到「谁、对谁、多少」 | 高：逐次精确 | 要 11 个版本的 RVA 和调用约定；在游戏主线程，只读、不改伤害 |

**建议**：先上 A（马上能用，solo 前就能看到分数），等 Gemini 把 B 的全版本地址和调用约定核出来后换成 B，两者对比校验一次再切换。
