# Warcraft III 全版本地图大小限制

## 结论摘要

- 地图大小拒绝在 `game.dll` 里，是 `CMP EAX, imm32` 后面紧跟近程 `JA`（`0F 87`）。大于阈值就离开成功路径。恰好等于阈值不会被这条 `JA` 拒绝。
- **1.0.17 到 1.23.0 的阈值是 `0x400000`（4 MiB）。1.24.1 起改为 `0x800000`（8 MiB）。** 常说的 8 MiB 限制就是这条比较；更早的版本同一处比较的是 4 MiB。
- 1.0.17 到 1.22 有 **3** 处。其中 NetProvider 读文件用的是短跳 `JA`（`77`），不是近程 `0F 87`。1.23 起 NetProvider 也改成近程 `JA`，仍然是 3 处。1.27 三处都由 REA/Ghidra 反编译确认：NetProvider 读文件、NetClient 网络事件 `0x3D`、NetRouter 网络事件 `0x41`。长度为 0 的拒绝是前面的另一条分支，补丁没有改它。
- 1.0.17 创建游戏时弹出「该地图太大了。请选择另外一张地图。」走的就是 NetProvider。函数入口 RVA `0x6DC6C0`，比较在文件偏移 `0x6DC72D`：`CMP EAX, 0x400000` / `JA short`。大于 4 MiB 时返回 `0x33`。第一版补丁只改了近程 `JA`，没有改到这里。
- 本机 `1.24.4.6387` 的 `game.dll` 这三处立即数已经是 `0xFF800000`，不是 8 MiB。无符号 `JA` 对普通地图大小不会成立。SHA-256：`c7c958174bde30961a41fa91827e78a800e473efdd8d1de8d6c94abf0b0024bf`。不要把它当成未改过的 1.24e。
- 补丁只把立即数改成 `0x7FFFFFFF`（2 GiB − 1）。`3D` 和 `JA` 不动。输出在 `patch/grok/dll_game/<版本>-map-size-unlock/game.dll`。没有做实机验证。
- `war3.exe`、`Storm.dll`、`worldedit.exe` 里没有同一条 `CMP EAX, 4MiB/8MiB` + `JA`。启动器现有的 `hookGameNetEventCheckMapSize` 仍会跳回原函数，去不掉这处比较。

## 范围与方法

样本是 `D:\Qt\workspace\War3Launcher\versions\<版本>\game.dll`，共 11 个版本。ImageBase 都是 `0x6f000000`。1.27 的 `.text` 文件偏移比 RVA 少 `0xC00`；更早版本这两列相同。

REA 6.4.0，provider 为 Ghidra 12.1.4。`D:` 是可移动卷，参与反编译的 DLL 先拷到 `C:\War3Analysis\samples\`，SHA-256 与原件一致后再分析。

| 版本 | 样本 SHA-256 | REA 反编译 |
| --- | --- | --- |
| 1.22.0.6328 | `5f866bd8a45951cd2c4b22b1c80a0329246dbed847540c85430376e8c4310c84` | 两处比较所在函数 |
| 1.23.0.6352 | `ee6175947a8792cd672253b37deb4c5d0577e4e145ffd90fed9021c64c31ae1e` | 1.23 新增的那一处 |
| 1.27.0.52240 | `e04d1716603c075eb0c8e1e21cf1093a664adc5249efab396bfa08d7b09d0c3a` | 三处全部 |

其余版本用同一条指令形态对齐：`3D` + `00 00 40 00` 或 `00 00 80 00` 或 `00 00 80 FF`，并且后面是 `0F 87`。每个这样的位置都只有地图大小这一种立即数。NetClient 那一处的直接调用 RVA 与 `war3hook.cpp` 里的 `g_offsetsForGameNetEventCheckMapSize[0]` 一致，调用目标与 `[1]` 一致。

## 1.27 三处函数

### NetClient：事件 `0x3D`

函数 `FUN_6f85f970`，入口 VA `0x6f85f970` / RVA `0x85F970` / 文件偏移 `0x85ED70`。比较在 VA `0x6f85f9b6` / RVA `0x85F9B6` / 文件偏移 `0x85EDB6`：

```text
0x6f85f9b6: CMP EAX, 0x800000
0x6f85f9bb: JA  0x6f85fb2f
```

反编译把解析失败、长度为零、长度大于 8 MiB 合成一个退出：

```c
iVar2 = FUN_6f852e60(&local_234);
if (((iVar2 == 0) || (local_12c == 0)) || (0x800000 < local_12c)) {
    FUN_6f771125();
    return;
}
```

调用它的是 `FUN_6f860ff0`（VA `0x6f860ff0`）。事件号在 `[ebp+0xC]` 的低 8 位，先 `DEC EAX`，再经 RVA `0x861408` 的字节表换成跳转表下标。跳转表在 RVA `0x861370`。事件 `0x3D` 减 1 后是 `0x3C`，字节表该项为 26，对应桩 `0x861286`，桩内 `E8` 的 RVA 是 `0x861291`，目标就是 `0x85F970`。这和启动器表里的 1.27 调用点相同。

### NetRouter：事件 `0x41`

函数 `FUN_6f872600`，入口 VA `0x6f872600` / RVA `0x872600` / 文件偏移 `0x871A00`。比较 RVA `0x872666` / 文件偏移 `0x871A66`。接受条件是解析成功、长度非 0，并且 `local_28 < 0x800001`，也就是长度不超过 8 MiB。函数体继续按玩家槽位 `+0xB4` 填写并转发给其他对象，形态是主机侧转发，不是 NetClient 那条接收路径。

分派函数 `FUN_6f871f70` 把事件号加上 `-0x1D`，与 `0x2F` 比较后走 RVA `0x8722B0` 的跳转表。下标 36 的桩是 `0x8721BC`，事件号为 `0x1D + 36 = 0x41`。

### NetProvider：按文件长度分配

函数 `FUN_6f84f4c0`，入口 VA `0x6f84f4c0` / RVA `0x84F4C0` / 文件偏移 `0x84E8C0`。比较 RVA `0x84F530` / 文件偏移 `0x84E930`。它调用 Storm `Ordinal_265` 取文件长度，接受条件是高 32 位为 0、低 32 位非 0，且 `uVar2 < 0x800001`。通过后用 `Ordinal_401` 分配缓冲区，断言字符串是 `NetProvider.cpp`。返回 `1` 表示成功，失败返回 `0x33` 或其他错误码。

因此这处补丁放宽的是读入地图文件时的长度，不是网络事件号。高 32 位仍必须为 0，大于等于 4 GiB 的长度不会被这次立即数修改放行。`0x7FFFFFFF` 仍在低 32 位里。

直接调用点是 thunk `FUN_6f84f490` 和 `FUN_6f84f630`。前者再被 RVA `0x85B9EF` 调用。

## 1.22 与 1.23

1.22 的两处都是 `CMP EAX, 0x400000` / `JA`。

- `FUN_6f66e4d0`（比较 VA `0x6f66e520`）与 1.27 的 NetClient 函数同构，接受条件是 `local_114 < 0x400001`。直接调用 RVA `0x671EAA`，与启动器表一致。REA 的 caller 列表是空的；调用关系来自这条 `E8 rel32`，目标就是该函数入口。
- `FUN_6f65ea30`（比较 VA `0x6f65ea8e`）与 1.27 的 NetRouter 函数同构，包括 `+0xB4` 槽位和 `0x400000` 标志测试。阈值同样是 `local_10 < 0x400001`。直接调用 RVA `0x662248`。

1.23 多出来的低地址比较在 VA `0x6f6494e3` / RVA `0x6494E3`。所在函数是 `FUN_6f649470`，不是往前最近的标准序言 `0x648DA0`（那是前一个函数）。反编译里同样是 Storm `Ordinal_265` / `Ordinal_401`，字符串为 `.\NetProvider.cpp`，接受条件含 `uVar2 < 0x400001`。这就是 1.23 新增的 NetProvider 读文件检查，阈值仍是 4 MiB。1.24 起这组立即数变成 8 MiB。

1.23 另外两处没有单独反编译。其中 RVA `0x670960` 的函数入口 `0x670910`、调用点 `0x6742FA` 与启动器 NetClient 表一致。

## 补丁

重新生成：`python patch/grok/dll_game/patch_all_versions_map_size.py`。脚本从 `versions\<版本>\game.dll` 复制，不改原件。

每处把立即数 4 字节换成 `FF FF FF 7F`。1.27 的三处文件偏移是 `0x84E931`、`0x85EDB7`、`0x871A67`（比较指令的下一字节）。补丁后 1.27 SHA-256 为 `fe1d90c31f81943dd80a2f771e4621872c4c63e21a2d7c61c66ae156ff3766b9`。各版本哈希写在对应目录的 `README.md`。

`NETERROR_MAPFILEBADSIZE` 只被错误文案分派引用，不是阈值指令。

## 尚未验证

静态补丁没有在游戏里打开过大地图。1.0.17–1.21 以及 1.24–1.26 里 NetClient 以外的比较点没有逐一反编译；它们被补丁改到，是因为指令和立即数与已反编译的检查相同。若某条路径用了别的常量或别的寄存器比较，这次扫描没有把它算进去。
