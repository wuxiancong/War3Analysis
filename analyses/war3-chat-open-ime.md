# 对局中输入法吃掉热键：聊天栏状态与输入法开关

- **分析模型**：Claude Opus 5.5
- **分析目的**：对局中关闭输入法（A / 技能 / 物品热键不再被吃），聊天时恢复
- **命名方式**：`war3-chat-open-ime`（检测对象 + 用途）
- **分析时间**：2026-11-21
- **验证状态**：全 11 版静态核对；Win32 输入法调用在独立测试窗口验证；1.27 实机通过（见「实机结果」），其它版本未实机验证
- **证据**：各版 `game.dll` 反汇编；`C:\War3Run\War3Launcher\logs\War3Keys.log`

## 现象

2026-11-21 21:21~21:30 实测 142 次 `WM_KEYDOWN` 是 0xE5（被输入法接走），其中 139 次在前 3 分钟；同期只收到 12 次 A。

## 游戏自己的处理

- 1.22+：编辑框得到 / 失去焦点时调用 SetIme（1.27 `0x153280`），写全局标志（1.27 `0xBDAA14`）并 `ImmAssociateContext`。实测仍然被吃键，说明对局中上下文仍可能是挂着的；具体是哪条路径挂回来的**未查明**。
- 1.0.17~1.21：不导入 `ImmAssociateContext`，从不关输入法。

所以不依赖那个全局标志，直接读聊天栏自己的开关。

## 实现（`war3hook.cpp` / `war3hook_jass.cpp`）

- 对局中、聊天栏关、hook 面板没有输入框激活：`ImmAssociateContext(hwnd, NULL)`，每 50ms 和每次按键复查。
- 聊天栏开 / 离开对局 / 读不到状态：`ImmAssociateContextEx(hwnd, NULL, IACE_DEFAULT)` 恢复。
- 已经变成 0xE5 的按键按扫描码还原。
- 不改系统输入法，不切键盘布局。

限制：对局中除聊天栏和 hook 面板以外的输入框（如存档 / 录像命名）不能用输入法打中文。

## 实机结果（2026-11-21，1.27）

- 22:23~22:25：对局中输入法两次被重新挂上（22:24:55、22:25:07），两次都被关掉。这局没按 A。
- 22:29~22:33：
  - A 42 次全部生效：40 次看到选目标；另 2 次在 31ms 内已发出攻击（比选目标检测的间隔短）。
  - Alt+Tab 切回（22:30:59）后第一次 A（22:31:04）生效；聊天关闭后的 36 次 A 全部生效。
  - 0xE5 共 11 次，全部在聊天栏打开期间（输入法正常工作），对局热键状态下 0 次。
  - 聊天里打中文并正常显示：用户确认通过。
  - 未核对：回大厅后打中文。

## 验收

| 操作 | 预期 | `War3Keys.log` |
|---|---|---|
| 中文输入法开着按 A / 技能键 | 立即生效 | `[IME] 对局中不在打字：关闭输入法`，随后 `[AKey] 收到 A` |
| 回车聊天打中文 | 出候选框、能发中文 | `[IME] 恢复输入法` |
