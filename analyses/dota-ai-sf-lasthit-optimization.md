# 影魔中路 AI 补刀优化：从 54% 到及格（2026-11-24）

| 字段 | 内容 |
| :--- | :--- |
| **分析模型** | Claude Opus 5.5（引擎事实部分引用 Gemini 4 Neon 的 `war3-lasthit-prediction-engine-facts.md`、`dota-ai-stealth-rune-route.md`） |
| **分析目的** | 把影魔（`Nfir`）中路 AI 补刀提到及格线，作为和用户 solo 的前提；同时记录哪些改法有效、哪些试过无效 |
| **命名方式** | `dota-ai-sf-lasthit-optimization`；导图 `dota-ai-sf-lasthit-optimization-mindmap.md`；离线分析脚本 `artifacts/lasthit-combat/lh_miss_classify.py`、`flight_measure.py` |

## 结论

| 局 | 口径 | 正补 | 反补 | 得分 | 备注 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 基线 | 旧口径（正反补合计命中率，及格 84） | 35/51 69% | 14/39 36% | 54（新口径约 73） | 原代码 |
| 11 | 新口径（正补率 + 反补率 × 0.1，及格 88） | 62/78 79% | 31/66 47% | 84 | 弹道飞行修正后 |
| 12 | 同上 | 68/81 84% | 16/64 25% | 86 | 瞄准进入斩杀线那一刻 |

| **16** | 同上 | **65/76 86%** | 21/60 35% | **89 ✅** | 复核窗口至少保留前摇开头 0.2s |

## 有效的改动（`War3Launcher/hooker/war3hook_ai.cpp` 等）

| 改动 | 依据 | 效果 |
| :--- | :--- | :--- |
| **弹道飞行按碰撞边缘算**：飞行距离 = 中心距离 − 100（影魔、小兵、塔都改） | Gemini 用 99 个补到的刀实测：`距离/1200` 中位偏差 −0.105s，减 100 后 −0.022s（影魔 `launchY=100`） | 「打早」从漏刀第一大类变成最少 |
| **防自动平 A 护盾提到补刀函数最前面**（`r.target == 0` 时看到抬手就 S，不 return） | 第 4 局 150s：AI 只决定出手 28 次，实际放出 54 刀，~30 刀是空闲自动攻击满血兵 | 不再把兵打残送人、不白占冷却 |
| **抬手复核**：抬手后用最新血量 / 在途弹道重算，落地前会被抢或落地时打不死就 S 取消；取消后立刻按新时机重出手（相当于重新瞄准） | 发令到落地 ~1.0s，发令时预判误差大 | 「出手 → 取消 → 重出手 → 补到」反复出现 |
| **复核窗口至少保留前摇开头 0.2s** | 中后期前摇 0.36~0.41s、指令延迟 0.3~0.5s，「剩余前摇 > 延迟 + 0.02」经常一帧都不成立 | 第 16 局及格 |
| **等补刀时保持面朝最低血兵**（偏 > 25° 就朝它迈 30 码），停用横向碎步 | War3Bot 锁步只有 10ms，「发令到抬手」0.14~0.43s 的大头是转身 | 延迟从 0.14~0.43 收窄到 0.2~0.33 |
| 一塔弹道 1200 → **750** | Gemini 核 6.83d `UnitFunc`：`e00R` / `u00M` Missilespeed=750 | 塔下预测不再快 60% |
| 只锁定目标、还没抬手的小兵多算 0.3s | `+0x6C` 在索敌 / 追击瞬间就写入（Gemini） | 少把还没开打的兵算成马上命中 |
| 影压：普攻来不及的单个残血兵也收（蓝 ≥ 160） | 原规则要一发 ≥ 2 个，前 4 分钟一次不放 | 每局影压 24~28 次，预计补 35~41 个 |
| 只贴近血 < 65% 的兵；扫描范围扩到 900（和计分口径一致） | 原来会走向站在近战兵后面的满血远程兵，挨打后撤漏刀 | 后撤次数减少 |
| 反补让给正补；有能补的敌兵就不先反补 | 新口径下反补只 ×0.1，一刀占 ~1.35s 冷却 | 正补率上升，反补率下降（预期内） |
| 同一目标连续取消 2 次，0.5s 内不再选它 | 预测来回跳时会反复抬手、卡住别的兵 | |

## 试过无效 / 撤回的

| 改动 | 结果 |
| :--- | :--- |
| 复核窗口放宽到伤害点前 0.10s（第 13 局） | 取消太多、取消后重抬手错过窗口，正补 84% → 71%，撤回（改成 0.2s 下限） |
| 补刀站位拉近到 0.55 倍射程 | 更容易吃近战兵仇恨，撤回 |
| 集火伤害在线校准系数 `g_aiIncScale` | 实测平均偏差接近 1（0.8~1.2 来回摆），保留但收窄到 0.7~1.3、平滑 0.1，作用很小 |
| 落点偏差校准 `impactBias` | 用的是和飞行修正前同一个公式，查不出 −0.1s 偏差；修正后平均 ±0.03s |

## 测试环境的坑

- **War3Launcher 日志失控**：一次会话写了 ~955 MB（`ipc_event.log` 167 MB、`ipc_message.log` 132 MB、`hero_picking.log` 103 MB…），Launcher 空转吃掉 4 核的 54~83%，游戏帧率掉到个位数、AI 节拍 170~290ms，第 13~14 局作废。重启 + 归档日志后恢复，但 Launcher 仍占 ~44%。用 `Scripts/Reset-War3LauncherLogs.ps1` 归档；根因未查。
- 监视日志用的 `tail -F` 在 Monitor 超时后没退出，占着 `AiUnit.log` 导致日志无法移动；后续一律 `timeout 1790 tail -F`。
- PowerShell 5.1 读无 BOM 的 UTF-8 脚本会乱码报语法错，新脚本都要带 BOM。
- 单局样本 50~80 个，标准误 ~5%；前几分钟样本 < 20 时的比较基本是噪声，要比完整一局。
