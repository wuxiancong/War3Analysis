- **分析模型**：Claude Opus 5.5
- **分析目的**：给「`-score start laning`」提供地图事实、引擎偏移、实现规则和实测结论
- **命名方式**：`dota-ai-laning-routine`（域 + 模块 + 用途），导图为正文名 + `-mindmap`
- **分析时间**：2026-11-22
- **验证状态**：1.27 + DotA 6.83d 近卫影魔单人实测 1 局完整 + 1 局中断（01:06:22–01:08:25，黑屏报告、war3 退出）。+ 1 局插眼对照（01:18 起）。**插眼失败根因已实锤：命令格式**；+ 1 局完整复测（01:34:51–01:46:57）：**插眼、补眼、符点视野已实机通过**；游戏钟、神符识别、影压冷却、瓶中符连按**仍有问题，未修**；天灾方和另外 10 个版本未实测
- **证据**：`War3Script/war3map.j`、地图 SLK / w3e / doo、各版 `game.dll` 原生注册表、`C:\War3Run\War3Launcher\logs\AiUnit.log`（2026-11-22 00:29:27–00:41:32）

## 流程与规则

1. **出门**：小鸡、树枝 ×3、大药、假眼；先放小鸡。
2. **插眼**：眼 (-1828,292)，站位 (-1828,12)，离上路符点 1454。成功只认充能减少。
3. **补刀**：到中路启动补刀计分；后撤一串最多 600，非危急不退过己方一塔。
4. **魔瓶**：补刀钱累计 ≥700 且现金 ≥700 → 远程买 → 小鸡取 → 运送。
5. **装符**：有瓶后每个偶数分钟 +1.5 s 出发。隐身 > 急速 > 双倍 > 幻象 > 恢复 > 金币；英雄 5 级时金币第一；残血 / 缺蓝时恢复第一。恢复符的排位是本次自定的，用户没有排。
6. **用符**：金币立即；双倍回线上后；恢复在缺血缺蓝且安全时；急速 / 隐身 / 幻象在撤退时。下次刷符前一律用掉或喝空，否则装不进。
7. **加点**：先不加，到线上见到敌兵再加。影魔默认 `211214122343335`；附近有队友对上敌方英雄、或有能杀的残血敌人时先学影压。其他英雄走自动加点优先级，能打时先点一个主动技能。
8. **影压补刀**：一发 ≥2 个优先；只有 1 个时，仅在普攻补不到或有兵等着反补时用，普攻留给反补。攻城车不算。缺点是推线。

## 第二次实测（01:06:22–01:08:25，中断）

| 项 | 结果 |
|---|---|
| 出门装、小鸡 | 全部到手，小鸡已放 |
| 插眼 | **失败**：01:07:06 / :08 / :10 发了 3 次，充能一直是 2；眼 → 符点方向 800 起全不可见。新的充能判据正确报了「眼没插上」 |
| 补刀、魔瓶、装符、影压、加点 | 没测到：号角 01:08:19 才响，约 6 s 后 war3 退出 |

插眼失败目前知道的：
- 命令被接受：0x11、flags 0x44、useslot 0xD002C 带物品对象 ID 已回显；由位置推算英雄在收到命令时停步（到眼位约 312，距离上限 420）。
- 不是禁插区：`R60`（9 个矩形，x 3456–4480、y -2624–-1920）不含眼位。在禁插区里会退还充能并删掉眼（`M6O` / `H3O` → `H1O`）。
- 推断：技能没有走到生效这一步。`M6O` 经 `NAO` 挂在 SPELL_EFFECT 上，一旦执行就无条件建 `o004`（只有禁插区会删掉并退充能）；而这里既没有视野也没有扣充能。未用施法事件实证。
- 对照测试：日志里没有玩家手动插眼的包可比。先让玩家在基地、眼位各手动插一次（ActionData2 会记下原始字节），再让 AI 在同样两点各插一次，逐字节比较并看充能。
- 因此第一局很可能也没插上（同一条命令，且判据是假的），「1555 贴着视野极限」不能再当作原因。

war3 退出与黑屏目前知道的：
- 用户在测试期间报告「War3貌似黑屏」；画面内容没有日志可查。
- 01:08:25.326 Launcher 收到进程退出；AiUnit / Spritehook / 网络日志都写到退出前 1–2 s 内，没有卡死迹象。
- **退出是用户看到黑屏后自己关闭的**（用户确认），不是崩溃。
- **黑屏原因未实锤**，也不能排除新 hook 的影响。已查到的：
  - EndScene 里画的内存面板每 5 s 一条「绘制中」，到 01:08:20 仍在：帧还在提交，但画面内容不可知（D3dxHook2 的贴图清单不能证明画面正常）。
  - 镜头相对英雄偏差一直 0.0，英雄在中路正常坐标：锁镜头没有把镜头带出地图。
  - 同样前 121 s，AI tick 平均间隔 127 ms，第一局 89 ms：这局明显更慢，原因未知。
  - 01:05:13 启动时报 405（等 IX86ver1.dll 超时，跳过该钩子），之后照常进局；和黑屏是否有关未知。
  - 两局都是 2560x1400、Direct3D、T&L 0；测试期间系统日志没有显示驱动事件。

### 查出的问题（均未修）

1. **游戏跑得比墙钟慢**：按 game_stats 的「当前游戏时间」，这局降到墙钟的 0.60；01:18 不开对线流程的对照局也是 0.58–0.86；00:30 第一局是 0.99。所以不是对线流程独有，原因未知（虚拟机负载、hook、别的都未排除）。
2. **AI 游戏钟算错**：`aiGameClock` = 墙钟 − 第一波时刻，按波次「四舍五入到 30 s」重对齐；游戏慢速时会多算波次。01:46:42 时 AI 587 s，实际约 447 s，快约 140 s。「6:01 / 8:01 / 10:01」三次出发时实际约 5:31 / 6:30 / 7:30。第一局全速，误差 ≤2 s。
3. **影压冷却、瓶中符间隔用墙钟**：0.6 倍速时 11.1 s 墙钟不到 7 s 游戏时间，1.7 s 也不够。两次「没放出」中 01:42:57 那次符合冷却未到；01:42:20 那次可能是 1.3 s 就核对、前摇还没结束。
4. **把用掉的神符当成地上的符**：枚举没有过滤死亡物品（地图自己的 `C9O` 要求 `GetWidgetLife>0`），而且 600 范围内取最后一个。第 3 次对着 (2602,-2562) 的「金币」按了 6 次：离符点 488，正是 01:41:55 用瓶中金币符时英雄所在（按速度推算）；`W0O` 用瓶中符时会在英雄脚下 `CreateItem` 再吃掉。按优先级选出来的方向因此也不可信。

修法：游戏时间取地图的计时（不用墙钟推算）；冷却和间隔按游戏时间、用背包 / 蓝量状态确认；枚举只收活着的物品并取离符点最近的。
